This page covers local flake usage that requires cloning the repository. For
remote flake usage, see the [README](https://github.com/moraxyc/deepseek-harness.nix).

## Cloning

```sh
git clone https://github.com/moraxyc/deepseek-harness.nix.git
cd deepseek-harness.nix
```

## Local Flake Usage

Run these commands from the repository root:

```sh
nix build .#dsh
nix build .#presets.tui
nix build .#bundles.tui
nix run .#default -- --version
nix run .#dsh-desktop
nix run .#dsh-desktop-official
```

`packages` provides `dsh`, `dsh-desktop`, `dsh-desktop-official`,
`dsh-desktop-unofficial`, `dsh-runtime`, and `dsh-workspace`.
`bundles.*` and `presets.*` are exposed through `legacyPackages`, so refs such
as `.#bundles.tui` and `.#presets.tui` work directly. `bundleCompositions.*` is
exposed the same way: `dsh` with one profile that selects a single bundle,
skipped for bundles the installation already carries. It exists to validate
bundle loading, not as a package to install. See
[Bundles and Presets](../catalog/) for the full catalog.

## Dev Shell

```sh
nix develop
```

The default dev shell includes `fetchrix`, `jq`, `nixfmt`, `pre-commit`,
`yq-go`, and the preparation tools. Pre-commit and flake checks run before push.

## Common Commands

```sh
nix fmt
nix flake check
nix build .#docs-site
cd docs-site
npm ci
npm run build
```

Update lock files with:

```sh
nix flake update
nix flake update --flake ./modules/flake-parts/dev
```

## Updating Packages

```sh
nix develop -c fetchrix update dsh-workspace
nix develop -c fetchrix update bundles.tui
```

`fetchrix.toml` declares version discovery, `prepare` artifacts, and `derive`
hashes. Package expressions consume `_sources/lock.json` and its artifacts through
`dshSources`; `fetchrixPackages` evaluates them with the new source. Commit
`_sources/` with the package changes. Fetchrix is pinned only in the development
flake; CI uses the same commands and skips broken packages.

## Removing Bundles

Remove the package implementation and keep its attribute name in
`lib/removed-bundles.nix`. Each entry must state the removal reason, the
user action, and the Migration Guide link. Keep the migration error on the
removed attribute; users select replacement bundles explicitly.

The overlay turns registry entries into `throw` errors. Package CI and catalog
generation use the same registry to select maintained attributes for evaluation.
Add the migration steps to all language versions of the
[Migration Guide](../migration/).

## Documentation

User-facing docs are maintained in English, Chinese, and Japanese under
`docs-site/src/content/docs/`, `docs-site/src/content/docs/zh/`, and
`docs-site/src/content/docs/ja/`. Keep release-specific upstream migration notes
in the [Migration Guide](../migration/) and its localized counterparts. Add a versioned
entry when an upstream update changes data formats, configuration ownership,
first-run imports, runtime downloads, or rollback behavior.

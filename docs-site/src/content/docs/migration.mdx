Read this page before updating this flake or its upstream workspace version.
It focuses on package removals and changes that may require action or affect
existing data.

## Before Upgrading

- Back up `$DSH_HOME` or the configured data directory.
- If a rollback may be needed, test with a separate data directory. Some
  migrations rewrite data in place.
- Check the target upstream version and read its entry below before the first
  launch.

## Desktop Default

`dsh-desktop` now launches `dsh-desktop-official` instead of
`dsh-desktop-unofficial`. To keep using the third-party application, select
`dsh-desktop-unofficial`. Overlay users should replace `pkgs.dsh.dsh-desktop`
with `pkgs.dsh.dsh-desktop-unofficial`. The NixOS and Home Manager module
defaults are unchanged.

Compatibility of configuration, sessions, and login state between the
applications has not been verified.

## Removed Bundles

Removed `bundles.*` attributes throw an error when evaluated. Select
replacement bundles explicitly in your configuration.

### `bundles.auto-mode`

[Upstream](https://github.com/NanmiCoder/dsh-auto-mode#readme) ended maintenance
on 2026-09-29 and archived the repository. Remove `bundles.auto-mode` from
`withBundles` and `programs.dsh.profiles.<name>.bundles`.

Before rebuilding, switch existing sessions to a built-in manual permission
mode, such as Workspace write. After rebuilding, restart Harness and start a
new session. Built-in Auto review is not policy-equivalent to the plugin's
Sandbox Auto and may grant broader access; select it only after reviewing the
current permission description. Keep existing session logs unchanged.

### `bundles.navbar`

[Upstream](https://github.com/vlln/dsh-navbar#readme) archived this plugin because
the official Web interface includes turn navigation. Remove `bundles.navbar`
from your bundle selections; use the built-in navigation in `bundles.web-app`.

### `bundles.billion-context`

[Upstream](https://github.com/Tyan66666/billion-context-dsh#readme) stopped
maintenance, fixes, and support. Remove `bundles.billion-context` from your
bundle selections. Upstream recommends
[ranxianglei/billion-context](https://github.com/ranxianglei/billion-context),
which supports DeepSeek Harness but is not packaged by this flake.

### `bundles.oh-dsh`

Oh-DSH is no longer maintained in this repository. Remove `bundles.oh-dsh`
from your bundle selections, including `withBundles` and
`programs.dsh.profiles.<name>.bundles`.

For the repository-maintained Web interface, use `presets.web` or select
`bundles.web-app`. These provide the standard Web composition maintained here.
Obtain the Oh-DSH distribution and its plugin set from the
[upstream project](https://github.com/hust-open-atom-club/oh-dsh).

Removing this bundle leaves existing data in place. Before switching
distributions, back up your data and check compatibility with the target
distribution. Carry out any required data migration yourself.

### `bundles.experimental-agent-team-profile`

Upstream removed this package in `0.2.2-rc.2`. Remove it from bundle selections
and remove `@deepseek-ai/dsh-experimental-agent-team-profile` from mutable
profiles. Enable Team per session with the built-in switch.

### `bundles.experimental-schedule-bundle`

This attribute was removed in upstream `0.2.1-alpha.1`. Remove it from your
bundle selections; `bundles.web-app` now includes Schedule. Follow the Schedule
instructions in the `0.2.1-alpha.1` entry below for profile and patch changes.

## `0.2.2-rc.2`

Before upgrading, read the [upstream release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.2)
and back up shared session storage.

### Team and session compatibility

Team uses named subagents and a per-session switch. Upgrade every process that
shares session storage before creating subagents, because earlier releases fail
to read the version 3 subagent catalog. Scripts pass `agent` instead of
`agent_id` and read `name` from delegation results. The interrupt tool is off by
default. Replace the experimental Agent Team package names in custom plugins
with `@deepseek-ai/dsh-agent-team` and `@deepseek-ai/dsh-tool-agent-team`.

### Worktrees and terminal profiles

Archiving a session removes eligible clean worktrees by default. Branches and
commits remain, and removal proceeds even when ignored files exist. Set
`worktree.config.retainOnArchive = true` to keep the directories. Rename profile
patch IDs `forge-worktree` to `worktree` and `optional-forge-panel` to
`forge-panel`.

`bundles.experimental-terminal-bundle` requires a Web or Desktop terminal
controller. Move overrides for `optional-terminal-bash` and
`optional-terminal-pwsh` to `optional-terminal-panel`, and check its updated
schema. Headless profiles compose `dsh-terminal`, `dsh-terminal-bash`, and
`dsh-tool-terminal` directly. Terminal output the agent is allowed to read can
enter model context and session logs.

### Search, Office, and Creator

- Web search uses the DeepSeek Search API by default. The Exa and Perplexity
  provider packages were removed, so review custom search settings. DeepSeek
  Search and Fetch accept `searchBilling` and `fetchBilling` set to `auto`,
  `account`, or `api-key`. The default can fall back to a signed-in account in
  sessions that use other model providers.
- In custom patches, replace `office-to-pdf` with `office-kit`. Office uses
  `office_render`, `office_convert`, and `office_recalculate`. Remove the old
  operation skills and the `skill-office.node` and `cli` settings. Saved standard
  and PTC presets need a `tool-office` row. Document parsing runs in the host
  process, outside the shell sandbox. To keep parsing inside the sandbox, omit
  this plugin.
- Creator uses `dsh-doc` in place of the four former development skills. The Nix
  installation keeps documentation, package sources, and templates that match
  the same version.

### Computer Use

CUA is an optional bundle that runs only on macOS. Existing `bundles.cua-bundle`
selections keep working. Upgrade custom scripts and helpers together to use
explicit windows, string element IDs, `getAccessibilityTree()`, and the new
keyboard API.

The Nix helper is built from the workspace source and ad-hoc signed instead of
fetched from npm. Regrant macOS permissions when macOS asks after switching or
updating the binary.

## `0.2.2-rc.1`

The [upstream release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.1)
summarize changes since `0.2.1-rc.5`. Compared with `0.2.2-alpha.3`, the source
changes only package versions, including the Cordis release versions.
No additional configuration migration is required from `alpha.3`. When upgrading
from an earlier release, also follow the `alpha.3` and `alpha.2` entries below.

`bundles.cpa`, `bundles.tui`, `bundles.turn-rewind`, and `bundles.vision-toolkit`
use downstream compatibility declarations for `0.2.2-rc.1` because their upstream
ranges exclude it. Startup was checked with isolated profiles. Verify the
features you use after upgrading.

## `0.2.2-alpha.3`

### Computer Use and worktrees

CUA moves from the shipped optional set to upstream's on-demand catalog.
`bundles.cua-bundle` remains available for declarative selection on
`aarch64-darwin`; add it explicitly to profiles that need Computer Use.
Grant Accessibility and Screen Recording permissions to `DSH Computer Use.app`,
not to the terminal.

When using `bundles.experimental-forge-bundle`, remove the standalone
`bundles.experimental-tool-worktree` from the same profile. Forge now provides
its worktree interface. For mutable profiles, also remove
`@deepseek-ai/dsh-experimental-tool-worktree` from `dsh.profile.bundles`.

### File modification policy

Read-before-write and external-change checks are now disabled by default;
sandbox restrictions and Review remain unchanged. Profiles requiring those
checks must explicitly restore the observation policy. For the Web profile:

```nix
programs.dsh.profiles.web.patch = [
  {
    id = "fs-observation-policy";
    disabled = false;
  }
];
```

See the [upstream release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-alpha.3).

### Previously incompatible bundles

`bundles.cpa`, `bundles.turn-rewind`, and `bundles.vision-toolkit` are available
again in this release and load without configuration changes. Their upstream
releases do not yet list `0.2.2-alpha.3` as supported, so check each plugin's
behavior after upgrading.

## `0.2.2-alpha.2`

### Runtime and tools

Node.js 24.9 or newer is required.

In custom profiles, remove `dsh-tools.mode` and `DSH_TOOLS_MODE`. Mount
`dsh-tool-executor-native` or `dsh-tool-executor-ptc`. Move `maxParallelSubCalls`
from `dsh-tools` to the PTC executor if using PTC. Shipped presets already select
an executor.

SSH protocol 3 requires a matching remote helper. Update custom Node PTC
bootstraps with the host. Caller-cancelled `run_code` now reports `ABORTED`.

### Plugins

- Import official bundle lists and profile templates from
  `@deepseek-ai/dsh-official-bundles`, not `dsh-app-boot`.
- Select models through `agent.model.select()` before step preparation.
  `agent/request` may no longer change the route or reasoning effort.
- Tool declarations no longer pass through `system-prompt/assemble`. Use
  step-time tool admission for conditional tools.
- Await Session projection registration and retain its handle. Custom approval
  compositions must provide `sessionProjections` and await service activation.
- Timer `throttle` and `debounce` wrappers return `void`. Awaiting them does not
  await the callback.

See the [upstream release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-alpha.2)
for the corresponding API upgrade guides.

### Optional bundles and deployment

The optional set adds personalized recommendations, LiveShare, Forge, and CUA.
Forge carries `git` and `gh`. GitHub operations require the user's own
authentication.

CUA is available only on `aarch64-darwin`.

Web Fetch now permits private-network destinations. Public or shared deployments
must enforce their own egress restrictions.

### Incompatible bundles

dsh skips a bundle at startup when its `@deepseek-ai/dsh-*` peer ranges or
`engines.dsh` exclude the running version, and prints
`skipping profile bundle`. The following bundles declare ranges that exclude
`0.2.2-alpha.2`, so dsh has not loaded them since this upgrade. They are now
marked broken, and evaluating them reports that instead of building a bundle
that never loads:

- `bundles.cpa`
- `bundles.plugin-check`
- `bundles.security-audit`
- `bundles.session-health`
- `bundles.turn-rewind`
- `bundles.vision-toolkit`

Remove them from `withBundles` and `programs.dsh.profiles.<name>.bundles`.
They return once upstream publishes a release that supports this dsh version.
`bundles.tui` was skipped the same way and now loads again.

Composed `dsh` packages now fail to build when a profile would skip a bundle or
disable a plugin row. If you package your own bundle with `buildDshBundle` and
have verified it against the dsh version in use, set
`dshEngines = "<version>"`; the builder writes it to `engines.dsh`, which dsh
checks instead of the peer ranges.

## `0.2.1-alpha.2`

### Services

Web listeners accept concrete IPv4 and IPv6 addresses, not wildcard addresses.
The predefined Nginx proxy brackets IPv6 addresses automatically. Native HTTPS
requires both `--tls-cert` and `--tls-key`; set `services.dsh.reverseProxy.scheme`
to `"https"` when using that proxy with a TLS backend. Client-facing Nginx TLS
is independent. See [service configuration](../advanced-usage/#reverse-proxy).

### Custom profiles and integrations

- `dsh-tools` no longer accepts `mode = "both"`; choose `"native"` or `"ptc"`
  in custom plugin patches. This is unrelated to Nix profile modes
  (`"managed"` and `"mutable"`).
- Shared instructions and skills use `DSH_AGENTS_HOME`, defaulting to
  `~/.agents`. `DSH_HOME` still controls Harness state. Services can set
  `services.dsh.environment.DSH_AGENTS_HOME` to a service-readable directory;
  the module does not redirect it automatically. Review custom
  `dsh-agent-instructions` settings against the current file-candidate schema.
- Python PTC now uses the selected sandbox policy. A missing restricted
  sandbox backend is an error; do not switch to full access to bypass it.
- Custom SDK clients and plugins need review against the updated
  `session/wait`, Agent Team Inbox, working-directory, dynamic tool-set, and
  system-prompt APIs. Bundled upstream consumers use the same release as the
  kernel. External clients must be updated to match this release.

## `0.2.1-alpha.1`

These notes apply when upgrading from `0.2.0-rc.2` and supersede the earlier
Schedule instructions.

### Schedule

The Web composition now mounts Schedule and its task page directly. The
`standard`, `cordis`, and `ptc` presets include the time context and Schedule
tools; `minimal` includes neither.

Upstream removes `@deepseek-ai/dsh-experimental-schedule-bundle` from a profile's
bundle list on startup, rewriting its `package.json`. Stored tasks and delivery
records are retained. Remove any explicit Nix reference to
`bundles.experimental-schedule-bundle`; evaluating it now fails with a migration
message directing you to `bundles.web-app`.

Keep overrides for `schedule` and `ui-schedule`. Remove top-level `time-context`
patches: that row now belongs to the agent preset. For managed profiles, make
these changes in `programs.dsh.profiles.<name>.patch`.

Nix warns when a structured profile or home-level patch targets the old
top-level `time-context` or invariant IDs listed below. Raw YAML strings and
runtime-managed files still need manual review.

### Plugin API

Upstream removed `@deepseek-ai/dsh-invariants` and every package's `/invariant`
export. Remove their imports and configuration rows, along with patches targeting
the old `sdk-minimal` IDs: `invariants`, `session-invariant`, `agent-invariant`,
`scope-invariant`, and `agent-loop-invariant`. Plugins using these APIs need an
update before they can load.

Subpath plugins no longer read display metadata from `<subpath>/package.json`.
Plugin authors must move titles and descriptions to locale `meta.title` and
`meta.description`, and export icons through `<subpath>/icon`. Package-root
metadata remains supported.

## `0.2.0-rc.1`

These notes apply when upgrading to upstream `dsh-v0.2.0-rc.1`. This is the
first preview release of the 0.2 line, and upstream states that both product
features and the plugin API keep changing. The `0.1.7-alpha.1` notes below still
apply.

### Preview notice

The first Web launch after the upgrade shows the preview notice again, because
upstream bumped its acknowledgement version to `2026-09-28.1`. The dialog is
expected and does not indicate a failed upgrade.

### Schedule

Upstream moved Schedule, its task page, and the time context out of the default
Web composition into the optional bundle
`@deepseek-ai/dsh-experimental-schedule-bundle`. Every composition ships it
switched off; enable it in the plugin manager to get Schedule back.

### Session-log upload

The official DeepSeek request field `dsh_session_log` now uploads through a
byte-bounded OTLP channel whose endpoint is
`dsh-otel-collector.deepseeksvc.com`, and its `enabled` flag became
runtime-mutable instead of fixed at startup. It stays enabled by default.

`DSH_TELEMETRY_DISABLED` still only disables the `session-telemetry-otel` row,
so it does not stop this upload. Use the **Upload Session Log when using the
official model API** switch in **Settings → General**, or set `enabled: false`
in the plugin configuration.

## `0.1.7-alpha.1`

These notes apply when upgrading to upstream `dsh-v0.1.7-alpha.1`. Keep them in
mind for later versions unless a newer entry supersedes them.

### Adapter configuration

The official DeepSeek adapter no longer reads `protocol`. Remove this key from
existing adapter settings and verify the Messages API configuration before the
first run.

### Session logs

Session logs migrate to V4 on disk. This is an in-place data migration:

- the first launch can change session files;
- reverting to an older Nix generation restores program files, not the old
  session format;
- restore the backup or use a separate `DSH_HOME` when testing an older
  generation.

### `settings.yaml` and managed profiles

The `settings.yaml` import runs once. Startup renames the source to
`settings.yaml.imported` before writing the new settings and does not retry the
source after a later overwrite. Keep a backup before the first launch.

In a `managed` profile, Nix owns `cordis.patch.yml`. Declare persistent values
through `programs.dsh.profiles.<name>.patch`, or use `mode = "mutable"` when
runtime Settings or `dsh plugin` changes must persist outside Nix.

### Agent Presets

For Nix-managed presets, alpha1 generates an
`@deepseek-ai/dsh-agent-preset` plugin declaration in the profile patch. It no
longer copies a separate preset directory to `$DSH_HOME/.agent-presets`.

If you previously edited files in that directory, move the intended
configuration to `programs.dsh.agentPresets`, `profiles.<name>.agentPreset`, or
the profile patch. Do not depend on the old directory being populated by Nix.

### Voice input

Voice input downloads its model at runtime on first use. Keep that cache
writable and include it in backups if it must survive a fresh profile or
data-directory setup. Offline use is available only after the model
has been downloaded successfully for the same runtime user.

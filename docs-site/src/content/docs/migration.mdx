---
title: Migration Guide
description: User actions and compatibility notes for upstream DeepSeek Harness changes.
---

Read this page before upgrading the upstream workspace version used by this
flake. It records changes that may require action or affect existing data.
Routine dependency updates are not listed here.

## Before Upgrading

- Back up `$DSH_HOME` or the configured data directory.
- If a rollback may be needed, test with a separate data directory. Some
  migrations rewrite data in place.
- Check the target upstream version and read its entry below before the first
  launch.

## `0.2.1-alpha.1`

These notes apply when upgrading from `0.2.0-rc.2` and supersede the earlier
Schedule instructions.

### Schedule

The Web composition now mounts Schedule and its task page directly. The
`standard`, `cordis`, and `ptc` presets include the time context and Schedule
tools; `minimal` includes neither.

Upstream removes `@deepseek-ai/dsh-experimental-schedule-bundle` from a profile's
bundle list on startup, rewriting its `package.json`. Stored tasks and delivery
records are retained. Remove any explicit Nix reference to
`bundles.experimental-schedule-bundle`; evaluating it now fails with a migration
message directing you to `bundles.web-app`.

Keep overrides for `schedule` and `ui-schedule`. Remove top-level `time-context`
patches: that row now belongs to the agent preset. For managed profiles, make
these changes in `programs.dsh.profiles.<name>.patch`.

Nix warns when a structured profile or home-level patch targets the old
top-level `time-context` or invariant IDs listed below. Raw YAML strings and
runtime-managed files still need manual review.

### Plugin API

Upstream removed `@deepseek-ai/dsh-invariants` and every package's `/invariant`
export. Remove their imports and configuration rows, along with patches targeting
the old `sdk-minimal` IDs: `invariants`, `session-invariant`, `agent-invariant`,
`scope-invariant`, and `agent-loop-invariant`. Plugins using these APIs need an
update before they can load.

Subpath plugins no longer read display metadata from `<subpath>/package.json`.
Plugin authors must move titles and descriptions to locale `meta.title` and
`meta.description`, and export icons through `<subpath>/icon`. Package-root
metadata remains supported.

## `0.2.0-rc.1`

These notes apply when upgrading to upstream `dsh-v0.2.0-rc.1`. This is the
first preview release of the 0.2 line, and upstream states that both product
features and the plugin API keep changing. The `0.1.7-alpha.1` notes below still
apply.

### Preview notice

The first Web launch after the upgrade shows the preview notice again, because
upstream bumped its acknowledgement version to `2026-09-28.1`. The dialog is
expected and does not indicate a failed upgrade.

### Schedule

Upstream moved Schedule, its task page, and the time context out of the default
Web composition into the optional bundle
`@deepseek-ai/dsh-experimental-schedule-bundle`. Every composition ships it
switched off; enable it in the plugin manager to get Schedule back.

### Session-log upload

The official DeepSeek request field `dsh_session_log` now uploads through a
byte-bounded OTLP channel whose endpoint is
`dsh-otel-collector.deepseeksvc.com`, and its `enabled` flag became
runtime-mutable instead of fixed at startup. It stays enabled by default.

`DSH_TELEMETRY_DISABLED` still only disables the `session-telemetry-otel` row,
so it does not stop this upload. Use the **Upload Session Log when using the
official model API** switch in **Settings → General**, or set `enabled: false`
in the plugin configuration.

## `0.1.7-alpha.1`

These notes apply when upgrading to upstream `dsh-v0.1.7-alpha.1`. Keep them in
mind for later versions unless a newer entry supersedes them.

### Adapter configuration

The official DeepSeek adapter no longer reads `protocol`. Remove this key from
existing adapter settings and verify the Messages API configuration before the
first run.

### Session logs

Session logs migrate to V4 on disk. This is an in-place data migration:

- the first launch can change session files;
- reverting to an older Nix generation restores program files, not the old
  session format;
- restore the backup or use a separate `DSH_HOME` when testing an older
  generation.

### `settings.yaml` and managed profiles

The `settings.yaml` import runs once. Startup renames the source to
`settings.yaml.imported` before writing the new settings and does not retry the
source after a later overwrite. Keep a backup before the first launch.

In a `managed` profile, Nix owns `cordis.patch.yml`. Declare persistent values
through `programs.dsh.profiles.<name>.patch`, or use `mode = "mutable"` when
runtime Settings or `dsh plugin` changes must persist outside Nix.

### Agent Presets

For Nix-managed presets, alpha1 generates an
`@deepseek-ai/dsh-agent-preset` plugin declaration in the profile patch. It no
longer copies a separate preset directory to `$DSH_HOME/.agent-presets`.

If you previously edited files in that directory, move the intended
configuration to `programs.dsh.agentPresets`, `profiles.<name>.agentPreset`, or
the profile patch. Do not depend on the old directory being populated by Nix.

### Voice input

Voice input downloads its model at runtime on first use. This flake does not
provide a separate Nix model output or relocate the upstream plugin cache.
Keep that cache writable and include it in backups if it must survive a fresh
profile or data-directory setup. Offline use is available only after the model
has been downloaded successfully for the same runtime user.

description: リポジトリのパッケージ削除と上流 DeepSeek Harness の移行に関する注記。
---

この flake またはその上流ワークスペースのバージョンを更新する前に、このページを読んでください。
ここでは、パッケージの削除と、対応が必要になる可能性や既存データへの影響がある変更に
焦点を当てます。

## アップグレード前に

- `$DSH_HOME` または設定済みのデータディレクトリをバックアップしてください。
- ロールバックが必要になる可能性がある場合は、別のデータディレクトリでテストしてください。一部の
  移行ではデータがその場で書き換えられます。
- 対象の上流バージョンを確認し、初回起動前に以下の該当する項目を読んでください。

## デフォルトのデスクトップアプリケーション

`dsh-desktop` が起動するアプリケーションを `dsh-desktop-unofficial` から
`dsh-desktop-official` に変更しました。サードパーティ版を使い続けるには、
`dsh-desktop-unofficial` を選択してください。overlay の利用者は
`pkgs.dsh.dsh-desktop` を `pkgs.dsh.dsh-desktop-unofficial` に変更してください。
NixOS と Home Manager のモジュールのデフォルト値は変わりません。

アプリケーション間の設定、セッション、ログイン状態の互換性は未検証です。

## 削除されたバンドル

削除された `bundles.*` 属性は、評価時にエラーを発生させます。設定で代替バンドルを明示的に選択してください。

### `bundles.auto-mode`

[上流](https://github.com/NanmiCoder/dsh-auto-mode#readme)は 2026-09-29 に保守を終了し、
リポジトリをアーカイブしました。`bundles.auto-mode` を `withBundles` と
`programs.dsh.profiles.<name>.bundles` から削除してください。

再ビルド前に、既存のセッションを Workspace write などの組み込みの手動権限モードに
切り替えてください。再ビルド後に Harness を再起動し、新しいセッションを開始してください。
組み込みの Auto review はプラグインの Sandbox Auto とポリシー上等価ではなく、より広範な
アクセスを許可する場合があります。現在の権限の説明を確認してから選択してください。
既存のセッションログは変更せずに保持してください。

### `bundles.navbar`

公式 Web インターフェイスにタブナビゲーションが含まれるため、
[上流](https://github.com/vlln/dsh-navbar#readme)はこのプラグインをアーカイブしました。
バンドル選択から `bundles.navbar` を削除し、`bundles.web-app` の組み込みナビゲーションを
使用してください。

### `bundles.billion-context`

[上流](https://github.com/Tyan66666/billion-context-dsh#readme)は保守、修正、サポートを
終了しました。バンドル選択から `bundles.billion-context` を削除してください。上流は
[ranxianglei/billion-context](https://github.com/ranxianglei/billion-context) を推奨していますが、
これは DeepSeek Harness をサポートしているものの、この flake ではパッケージ化されていません。

### `bundles.oh-dsh`

Oh-DSH はこのリポジトリでは保守されなくなりました。`bundles.oh-dsh` を、`withBundles` と
`programs.dsh.profiles.<name>.bundles` を含むバンドル選択から削除してください。

リポジトリで保守されている Web インターフェイスには、`presets.web` を使用するか、
`bundles.web-app` を選択してください。これらはここで保守されている標準の Web 構成を提供します。
Oh-DSH ディストリビューションとそのプラグインセットは、
[上流プロジェクト](https://github.com/hust-open-atom-club/oh-dsh)から入手してください。

このバンドルを削除しても既存データは残ります。ディストリビューションを切り替える前に、
データをバックアップし、移行先ディストリビューションとの互換性を確認してください。
必要なデータ移行は自身で行ってください。

### `bundles.experimental-schedule-bundle`

この属性は上流の `0.2.1-alpha.1` で削除されました。バンドル選択から削除してください。
`bundles.web-app` に Schedule が含まれるようになりました。プロファイルとパッチの変更については、
以下の `0.2.1-alpha.1` の項目にある Schedule の手順に従ってください。

## `0.2.2-alpha.3`

### Computer Use とワークツリー

CUA は同梱のオプション集合から上流のオンデマンドカタログへ移動しました。
`bundles.cua-bundle` は引き続き `aarch64-darwin` で宣言的に選択できます。
Computer Use が必要なプロファイルに明示的に追加してください。
ターミナルではなく、`DSH Computer Use.app` にアクセシビリティと画面収録の権限を付与してください。

`bundles.experimental-forge-bundle` を使用する場合、同じプロファイルから
単独の `bundles.experimental-tool-worktree` を削除してください。
ワークツリーの入口は Forge に統合されました。mutable プロファイルでは、
`dsh.profile.bundles` から `@deepseek-ai/dsh-experimental-tool-worktree` も削除してください。

### ファイル変更ポリシー

書き込み前の読み取り確認と外部変更の確認は、デフォルトで無効になりました。
サンドボックス制限と Review は変わりません。確認が必要なプロファイルでは、
観測ポリシーを明示的に復元してください。Web プロファイルの例：

```nix
programs.dsh.profiles.web.patch = [
  {
    id = "fs-observation-policy";
    disabled = false;
  }
];
```

詳細は[上流のリリースノート](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-alpha.3)を参照してください。

## `0.2.2-alpha.2`

### ランタイムとツール

Node.js 24.9 以降が必要です。

カスタムプロファイルでは、`dsh-tools.mode` と `DSH_TOOLS_MODE` を削除してください。
`dsh-tool-executor-native` または `dsh-tool-executor-ptc` をマウントしてください。
PTC を使用する場合は、`maxParallelSubCalls` を `dsh-tools` から PTC エグゼキューターへ移動します。
同梱のプリセットでは、すでにエグゼキューターが選択されています。

SSH プロトコル 3 には、対応するリモートヘルパーが必要です。カスタムの Node PTC
ブートストラップもホスト側に合わせて更新してください。呼び出し元がキャンセルした `run_code` は、
`ABORTED` を報告するようになりました。

### プラグイン

- 公式バンドルリストとプロファイルテンプレートは、
  `@deepseek-ai/dsh-official-bundles` からインポートし、`dsh-app-boot` からはインポートしないでください。
- ステップ準備の前に `agent.model.select()` でモデルを選択してください。
  `agent/request` ではルートや推論レベルを変更できなくなりました。
- ツール宣言は `system-prompt/assemble` を通過しなくなりました。条件付きツールには、
  ステップ実行時のツール許可を使用してください。
- Session プロジェクションの登録完了を待ち、そのハンドルを保持してください。カスタムの承認構成では、
  `sessionProjections` を提供し、サービスのアクティベーション完了を待つ必要があります。
- Timer の `throttle` ラッパーと `debounce` ラッパーは `void` を返します。これらを待機しても、
  コールバックの完了は待機しません。

対応する API アップグレードガイドについては、
[上流のリリースノート](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-alpha.2)を
参照してください。

### オプションバンドルとデプロイ

オプションセットでは、パーソナライズされたレコメンド、LiveShare、Forge、CUA が追加されます。
Forge には `git` と `gh` が同梱されます。GitHub 操作にはユーザー自身の認証が必要です。

CUA は `aarch64-darwin` でのみ利用できます。

Web Fetch はプライベートネットワーク上の宛先を許可するようになりました。公開環境または
共有環境へのデプロイでは、独自の外部送信（egress）制限を適用する必要があります。

### 互換性のないバンドル

`@deepseek-ai/dsh-*` のピアバージョン範囲または `engines.dsh` が実行中のバージョンを
除外する場合、dsh は起動時にそのバンドルをスキップし、`skipping profile bundle` を出力します。
以下のバンドルは `0.2.2-alpha.2` を除外する範囲を宣言しているため、このアップグレード以降、
dsh はそれらを読み込んでいませんでした。現在では、これらは broken とマークされており、
評価すると、読み込まれることのないバンドルをビルドする代わりにその旨が報告されます：

- `bundles.cpa`
- `bundles.plugin-check`
- `bundles.security-audit`
- `bundles.session-health`
- `bundles.turn-rewind`
- `bundles.vision-toolkit`

これらを `withBundles` と `programs.dsh.profiles.<name>.bundles` から削除してください。
上流がこの dsh バージョンをサポートするリリースを公開すれば、再び利用できるようになります。
`bundles.tui` も同様にスキップされていましたが、現在は再び読み込まれます。

構成済みの `dsh` パッケージは、プロファイルがバンドルをスキップする、またはプラグイン行を
無効化する場合に、ビルドが失敗するようになりました。`buildDshBundle` で独自のバンドルを
パッケージ化し、使用する dsh バージョンとの互換性を検証済みの場合は、
`dshEngines = "<version>"` を設定してください。ビルダーはこれを `engines.dsh` に書き込み、
dsh はピアバージョン範囲の代わりにこの値を確認します。

## `0.2.1-alpha.2`

### サービス

Web リスナーはワイルドカードアドレスではなく、具体的な IPv4 アドレスと IPv6 アドレスを
受け付けます。定義済みの Nginx プロキシは IPv6 アドレスを自動的に角括弧で囲みます。
ネイティブ HTTPS には `--tls-cert` と `--tls-key` の両方が必要です。そのプロキシを TLS
バックエンドとともに使用する場合は、`services.dsh.reverseProxy.scheme` を `"https"` に
設定してください。クライアント側の Nginx TLS は独立しています。
[サービス設定](../advanced-usage/#リバースプロキシ)を参照してください。

### カスタムプロファイルと統合

- `dsh-tools` は `mode = "both"` を受け付けなくなりました。カスタムプラグインパッチでは、
  `"native"` または `"ptc"` を選択してください。これは Nix プロファイルモード
  （`"managed"` と `"mutable"`）とは無関係です。
- 共有 instructions と skills には `DSH_AGENTS_HOME` を使用し、デフォルトは `~/.agents` です。
  `DSH_HOME` は引き続き Harness の状態を制御します。サービスでは、
  `services.dsh.environment.DSH_AGENTS_HOME` にサービスから読み取り可能なディレクトリを
  設定できます。モジュールが自動的にリダイレクトすることはありません。カスタムの
  `dsh-agent-instructions` 設定を現行の file-candidate スキーマと照らし合わせて確認してください。
- Python PTC は選択されたサンドボックスポリシーを使用するようになりました。制限付き
  サンドボックスバックエンドが見つからない場合はエラーになります。これを回避するために
  フルアクセスへ切り替えないでください。
- カスタム SDK クライアントとプラグインは、更新された `session/wait`、Agent Team Inbox、
  作業ディレクトリ、動的ツールセット、system-prompt の各 API と照らし合わせて確認する必要があります。
  バンドルされている上流のコンシューマーはカーネルと同じリリースを使用します。
  外部クライアントは、このリリースに合わせて更新する必要があります。

## `0.2.1-alpha.1`

これらの注記は `0.2.0-rc.2` からのアップグレード時に適用され、以前の Schedule 手順に優先します。

### Schedule

Web 構成は Schedule とそのタスクページを直接マウントするようになりました。
`standard`、`cordis`、`ptc` の各プリセットには時間コンテキストと Schedule ツールが含まれますが、
`minimal` にはどちらも含まれません。

上流は起動時にプロファイルのバンドルリストから
`@deepseek-ai/dsh-experimental-schedule-bundle` を削除し、その `package.json` を書き換えます。
保存済みタスクと配信記録は保持されます。`bundles.experimental-schedule-bundle` への明示的な
Nix 参照は削除してください。現在では、これを評価すると `bundles.web-app` を案内する移行
メッセージとともに失敗します。

`schedule` と `ui-schedule` のオーバーライドは保持してください。トップレベルの `time-context`
パッチは削除してください。この行は現在はエージェントプリセットに属しています。管理対象
プロファイルでは、これらの変更を `programs.dsh.profiles.<name>.patch` で行ってください。

構造化プロファイルまたはホームレベルのパッチが、古いトップレベルの `time-context` または
以下に列挙する invariant ID を対象としている場合、Nix は警告を表示します。未加工の YAML
文字列とランタイム管理ファイルは、引き続き手動で確認する必要があります。

### プラグイン API

上流は `@deepseek-ai/dsh-invariants` と、すべてのパッケージの `/invariant` エクスポートを
削除しました。これらのインポートと設定行に加え、古い `sdk-minimal` ID（`invariants`、
`session-invariant`、`agent-invariant`、`scope-invariant`、`agent-loop-invariant`）を対象とする
パッチも削除してください。これらの API を使用するプラグインは、読み込む前に更新が必要です。

サブパスプラグインは `<subpath>/package.json` から表示メタデータを読み取らなくなりました。
プラグイン作者は、タイトルと説明をロケールの `meta.title` と `meta.description` に移動し、
アイコンを `<subpath>/icon` からエクスポートする必要があります。パッケージルートの
メタデータは引き続きサポートされます。

## `0.2.0-rc.1`

これらの注記は上流の `dsh-v0.2.0-rc.1` へのアップグレード時に適用されます。これは 0.2 系の
最初のプレビューリリースであり、上流は製品機能とプラグイン API の両方が今後も変更されると
述べています。以下の `0.1.7-alpha.1` の注記も引き続き適用されます。

### プレビュー通知

上流が確認バージョンを `2026-09-28.1` に引き上げたため、アップグレード後の初回 Web 起動時に
プレビュー通知が再び表示されます。このダイアログは想定どおりの動作であり、アップグレードの
失敗を示すものではありません。

### Schedule

上流は Schedule、そのタスクページ、時間コンテキストをデフォルトの Web 構成からオプション
バンドル `@deepseek-ai/dsh-experimental-schedule-bundle` へ移動しました。すべての構成でオフの
状態で同梱されるため、Schedule を再び使用するにはプラグインマネージャーで有効にしてください。

### セッションログのアップロード

公式 DeepSeek リクエストフィールド `dsh_session_log` は、エンドポイントが
`dsh-otel-collector.deepseeksvc.com` である、バイト数に上限のある OTLP チャネルを通じて
アップロードされるようになりました。また、その `enabled` フラグは起動時に固定されるのではなく、
実行時に変更可能になりました。デフォルトでは有効なままです。

`DSH_TELEMETRY_DISABLED` は引き続き `session-telemetry-otel` の行だけを無効にするため、
このアップロードは停止しません。**設定 → 全般**にある**公式モデル API 使用時にセッションログを
アップロード**スイッチを使用するか、プラグイン設定で `enabled: false` を設定してください。

## `0.1.7-alpha.1`

これらの注記は上流の `dsh-v0.1.7-alpha.1` へのアップグレード時に適用されます。新しい項目に
よって置き換えられない限り、それ以降のバージョンでも考慮してください。

### アダプター設定

公式 DeepSeek アダプターは `protocol` を読み取らなくなりました。既存のアダプター設定から
このキーを削除し、初回実行前に Messages API の設定を確認してください。

### セッションログ

ディスク上のセッションログは V4 に移行されます。これはデータをその場で移行する処理です：

- 初回起動時にセッションファイルが変更される可能性があります。
- 古い Nix 世代へ戻しても、プログラムファイルは復元されますが、古いセッション形式は復元されません。
- 古い世代をテストする場合は、バックアップを復元するか、別の `DSH_HOME` を使用してください。

### `settings.yaml` と管理対象プロファイル

`settings.yaml` のインポートは 1 回だけ実行されます。起動時に、新しい設定を書き込む前に
ソースが `settings.yaml.imported` へ名前変更されるため、後から上書きしてもソースの再試行は
行われません。初回起動前にバックアップを保持してください。

`managed` プロファイルでは、Nix が `cordis.patch.yml` を所有します。永続的な値は
`programs.dsh.profiles.<name>.patch` で宣言するか、`mode = "mutable"` を使用してください。
後者は、実行時の設定や `dsh plugin` による変更を Nix の外部で永続化する必要がある場合に適しています。

### エージェントプリセット

Nix で管理されるプリセットでは、alpha1 がプロファイルパッチ内に
`@deepseek-ai/dsh-agent-preset` プラグイン宣言を生成します。個別のプリセットディレクトリを
`$DSH_HOME/.agent-presets` にコピーすることはなくなりました。

以前にそのディレクトリ内のファイルを編集していた場合は、必要な設定を
`programs.dsh.agentPresets`、`profiles.<name>.agentPreset`、またはプロファイルパッチへ移動して
ください。Nix が古いディレクトリを生成することを前提にしないでください。

### 音声入力

音声入力は、初回使用時に実行時にモデルをダウンロードします。新しいプロファイルまたはデータ
ディレクトリを設定した後もキャッシュを維持する必要がある場合は、そのキャッシュを書き込み
可能な状態に保ち、バックアップに含めてください。オフラインで使用できるのは、同じ実行時
ユーザーでモデルのダウンロードが正常に完了した後だけです。

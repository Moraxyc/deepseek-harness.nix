title: 迁移说明
description: 仓库包移除与上游 DeepSeek Harness 变更的迁移说明。
---

更新这个 flake 或其上游 workspace 版本前，请先阅读本文。本文记录包移除，以及
可能需要用户操作或影响现有数据的变更。

## 升级前

- 备份 `$DSH_HOME` 或配置的数据目录。
- 如果可能需要回滚，请使用独立的数据目录测试。部分迁移会原地改写数据。
- 确认目标上游版本，并在首次启动前阅读对应条目。

## 已移除的 Bundle

已移除的 `bundles.*` 属性作为迁移入口保留，求值时通过 `throw` 告知原因与处理方法。
统一名单位于 `lib/removed-bundles.nix`。受支持的包目录和 CI 构建目标选择由本仓库
维护的属性。请在配置中显式选择替代 bundle。

### `bundles.auto-mode`

[上游](https://github.com/NanmiCoder/dsh-auto-mode#readme)已于 2026-09-29 停止维护并
归档仓库。请从 `withBundles` 和 `programs.dsh.profiles.<name>.bundles` 中删除
`bundles.auto-mode`。

重新构建前，请将已有会话切换到内置的手动权限模式，例如 Workspace write。重新构建后，
重启 Harness 并新建会话。内置 Auto review 与插件的 Sandbox Auto 权限策略并不等价，
可能授予更广的访问权限；选择前请先阅读当前权限说明。保留已有会话日志，不要改写。

### `bundles.navbar`

[上游](https://github.com/vlln/dsh-navbar#readme)因官方 Web 界面已内置回合导航而归档
此插件。请从 bundle 选择中删除 `bundles.navbar`，使用 `bundles.web-app` 的内置导航。

### `bundles.billion-context`

[上游](https://github.com/Tyan66666/billion-context-dsh#readme)已停止维护、修复与支持。
请从 bundle 选择中删除 `bundles.billion-context`。上游推荐
[ranxianglei/billion-context](https://github.com/ranxianglei/billion-context)，
该项目支持 DeepSeek Harness，但本 flake 尚未打包。

### `bundles.oh-dsh`

本仓库不再维护 Oh-DSH。请从 bundle 选择中删除 `bundles.oh-dsh`，包括
`withBundles` 和 `programs.dsh.profiles.<name>.bundles` 中的引用。

如需本仓库维护的 Web 界面，请使用 `presets.web` 或选择 `bundles.web-app`。
它们提供本仓库维护的标准 Web 组合。Oh-DSH 发行版及其插件组合请从
[上游项目](https://github.com/hust-open-atom-club/oh-dsh) 获取。

移除该 bundle 后，已有数据保留在原位置。切换发行版前，请备份数据并确认目标发行版的
兼容性；如需迁移数据，请自行完成。

### `bundles.experimental-schedule-bundle`

该属性已在上游 `0.2.1-alpha.1` 中移除。请从 bundle 选择中删除它；
`bundles.web-app` 现在直接包含 Schedule。profile 和 patch 的调整方法见下方
`0.2.1-alpha.1` 条目的 Schedule 说明。

## `0.2.2-alpha.2`

### 运行时与工具

要求 Node.js 24.9 或更新版本。

自定义 profile 应移除 `dsh-tools.mode` 和 `DSH_TOOLS_MODE`，挂载
`dsh-tool-executor-native` 或 `dsh-tool-executor-ptc`。使用 PTC 时，将
`maxParallelSubCalls` 从 `dsh-tools` 移至 PTC 执行器。随包提供的 preset 已选择执行器。

SSH 协议 3 要求远端 helper 与宿主匹配。自定义的 Node PTC bootstrap 也应同步
更新。由调用方取消的 `run_code` 现在返回 `ABORTED`。

### 插件

- 官方 bundle 列表与 profile 模板改从 `@deepseek-ai/dsh-official-bundles` 导入，
  不再从 `dsh-app-boot` 导入。
- 在步骤准备前通过 `agent.model.select()` 选择模型。`agent/request` 不再允许
  改变路由或推理强度。
- 工具声明不再经过 `system-prompt/assemble`，条件工具应使用步骤级准入。
- 等待 Session projection 注册并保留句柄。自定义审批组合必须提供
  `sessionProjections`，并等待服务激活。
- Timer 的 `throttle`、`debounce` 包装函数返回 `void`，等待包装函数不会等待回调。

相关 API 升级指南见[上游发版说明](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-alpha.2)。

### 可选 bundle 与部署

可选集合新增个性化推荐、LiveShare、Forge 和 CUA。Forge 携带 `git` 和 `gh`。
GitHub 操作使用用户自行配置的认证。

受当前固定的 Swift 工具链限制，CUA 仅在 `aarch64-darwin` 可用。
Nix 在应用启动前构建原生 helper。

Web Fetch 现在允许访问私网地址。公开或共享部署必须自行限制出站网络访问。

### 不兼容的 bundle

bundle 的 `@deepseek-ai/dsh-*` peer 范围或 `engines.dsh` 不包含当前运行版本时，dsh
会在启动时跳过它，并输出 `skipping profile bundle`。以下 bundle 声明的范围不包含
`0.2.2-alpha.2`，自本次升级起 dsh 并未加载它们。现已标记为 broken，求值时会直接
报告这一点，而不是构建一个永远不会加载的 bundle：

- `bundles.cpa`
- `bundles.plugin-check`
- `bundles.security-audit`
- `bundles.session-health`
- `bundles.turn-rewind`
- `bundles.vision-toolkit`

请从 `withBundles` 和 `programs.dsh.profiles.<name>.bundles` 中删除它们。上游发布
支持该 dsh 版本的版本后，这些 bundle 会恢复。`bundles.tui` 此前也以同样方式被跳过，
现已恢复加载。

组合后的 `dsh` 包在 profile 会跳过 bundle 或禁用插件行时会构建失败。如果你用
`buildDshBundle` 自行打包 bundle，并已针对当前固定的 dsh 版本验证过，可设置
`dshEngines = "<version>"`；builder 会将其写入 `engines.dsh`，dsh 随后以此代替 peer
范围进行检查。

## `0.2.1-alpha.2`

### 服务

Web 监听支持具体的 IPv4 和 IPv6 地址，不接受通配地址。预定义的 Nginx 反代会
自动为 IPv6 地址添加方括号。原生 HTTPS 要求同时传入 `--tls-cert` 和
`--tls-key`；使用该反代连接 TLS 后端时，将 `services.dsh.reverseProxy.scheme`
设为 `"https"`。客户端到 Nginx 的 TLS 配置独立。参见
[服务配置](../advanced-usage/#反向代理)。

### 自定义 profile 与集成

- `dsh-tools` 不再接受 `mode = "both"`；自定义插件 patch 应选择 `"native"` 或
  `"ptc"`。这与 Nix profile 的 `"managed"`、`"mutable"` 模式无关。
- 共享指令和技能使用 `DSH_AGENTS_HOME`，默认目录为 `~/.agents`；`DSH_HOME`
  仍然控制 Harness 状态目录。服务可以将
  `services.dsh.environment.DSH_AGENTS_HOME` 设为服务可读的目录，模块不会自动
  重定位它。自定义的 `dsh-agent-instructions` 配置应按当前文件候选项 schema 检查。
- Python PTC 现在使用所选的 sandbox policy。缺少受限 sandbox 后端会报错，
  不要切换为 full access 来绕过它。
- 自定义 SDK 客户端和插件需要检查 `session/wait`、Agent Team Inbox、
  working-directory、动态工具集合和 system-prompt API 的变化。随包提供的
  上游调用方与 kernel 使用同一版本；本 flake 不为外部客户端提供兼容层。

## `0.2.1-alpha.1`

以下内容适用于从 `0.2.0-rc.2` 升级，并覆盖此前的 Schedule 说明。

### Schedule

Web 组合现在直接挂载 Schedule 和任务页面。`standard`、`cordis` 和 `ptc` preset
包含时间上下文与 Schedule 工具；`minimal` 两者都不包含。

上游会在启动时从 profile 的 bundle 列表中删除
`@deepseek-ai/dsh-experimental-schedule-bundle`，并重写其 `package.json`。
已保存的任务和投递记录会保留。请删除 Nix 配置中显式引用的
`bundles.experimental-schedule-bundle`；求值该属性会报出迁移错误，并提示改用
`bundles.web-app`。

保留对 `schedule` 和 `ui-schedule` 的覆盖，删除顶层的 `time-context` patch：
该行现在属于 agent preset。managed profile 请在
`programs.dsh.profiles.<name>.patch` 中修改。

结构化的 profile 或 home-level patch 若指向旧的顶层 `time-context` 或下方列出的
invariant ID，Nix 会发出警告。原始 YAML 字符串和运行时管理的文件仍需手动检查。

### 插件 API

上游移除了 `@deepseek-ai/dsh-invariants` 和各包的 `/invariant` 导出。请删除相关
导入、配置行，以及指向旧 `sdk-minimal` ID 的 patch：`invariants`、
`session-invariant`、`agent-invariant`、`scope-invariant` 和 `agent-loop-invariant`。
使用这些 API 的插件需要更新后才能加载。

子路径插件不再从 `<子路径>/package.json` 读取展示信息。插件作者需要将标题和描述
移至 locale 的 `meta.title`、`meta.description`，并通过 `<子路径>/icon` 导出图标。
包根级别的元数据仍受支持。

## `0.2.0-rc.1`

以下内容适用于升级到上游 `dsh-v0.2.0-rc.1`。这是 0.2 系列的首个预览版，上游说明
产品功能和插件 API 都会继续变化。下方 `0.1.7-alpha.1` 的内容同样适用。

### 预览版说明

升级后首次打开 Web 端会再次显示预览版说明，因为上游把确认版本提升到
`2026-09-28.1`。该弹窗属于预期行为，不代表升级失败。

### Schedule

上游把 Schedule、其任务页面和时间上下文从默认 Web 组合移出，改为可选 bundle
`@deepseek-ai/dsh-experimental-schedule-bundle`。每个组合都随包携带它且默认关闭，
在插件管理页启用即可恢复 Schedule。

### Session 日志上传

官方 DeepSeek 请求字段 `dsh_session_log` 改为通过有字节上限的 OTLP 通道上传，端点为
`dsh-otel-collector.deepseeksvc.com`；`enabled` 也从启动时固定改为运行时可变更。
默认仍然开启。

`DSH_TELEMETRY_DISABLED` 依旧只关闭 `session-telemetry-otel` 这一行，不会停止该上传。
如需停止，请使用**设置 → 通用**中的**在使用官方模型 API 时上传 Session Log**开关，
或在插件配置中设置 `enabled: false`。

## `0.1.7-alpha.1`

以下内容适用于升级到上游 `dsh-v0.1.7-alpha.1`。后续版本如果没有新的条目覆盖，
也请继续注意这些行为。

### Adapter 配置

官方 DeepSeek adapter 不再读取 `protocol`。首次运行前，从现有 adapter 配置中删除
这个键，并重新检查 Messages API 配置。

### Session 日志

Session 日志会在磁盘上迁移到 V4。这是一次原地数据迁移：

- 首次启动可能会改写会话文件；
- 回退到旧 Nix generation 只能恢复程序文件，不能恢复旧的会话格式；
- 测试旧 generation 时，请恢复备份或使用独立的 `DSH_HOME`。

### `settings.yaml` 与 managed profile

`settings.yaml` 只导入一次。启动时会先把源文件改名为
`settings.yaml.imported`，再写入新设置；之后即使源文件被覆盖，也不会再次导入。
首次启动前请保留备份。

在 `managed` profile 中，`cordis.patch.yml` 由 Nix 所有。需要持久化的值应通过
`programs.dsh.profiles.<name>.patch` 声明；如果运行时 Settings 或 `dsh plugin` 的
修改需要在 Nix 之外保留，请使用 `mode = "mutable"`。

### Agent Preset

对于 Nix 管理的 preset，alpha1 会在 profile patch 中生成
`@deepseek-ai/dsh-agent-preset` 插件声明，不再把独立的 preset 目录复制到
`$DSH_HOME/.agent-presets`。

如果之前直接修改过这个目录，请将需要保留的配置迁移到
`programs.dsh.agentPresets`、`profiles.<name>.agentPreset` 或 profile patch。不要再
依赖 Nix 填充旧目录。

### 语音输入

语音输入会在首次使用时于运行时下载模型。本 flake 没有提供独立的 Nix 模型输出，
也不会重定位上游插件的缓存目录。如果需要在重新生成 profile 或数据目录后保留模型，
请保证缓存可写并纳入备份。只有同一运行用户成功下载模型后，才能按缓存实现离线使用。
